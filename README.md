# Прогноз оттока абонентов

Проект оценивает риск ухода абонента в ближайшие 30 дней. Такой прогноз помогает определить, с кем из абонентов связаться в первую очередь при ограниченном бюджете на удержание. На входе используются синтетические записи о звонках, SMS и мобильном интернете (CDR). Конвейер проверяет и агрегирует эти записи, сравнивает логистическую регрессию со случайным лесом и сохраняет выбранную модель с результатами оценки.

В стандартном запуске признаки строятся по событиям, доступным на начало **30 ноября 2025 года**. Целевая переменная показывает, ушёл ли абонент в период с 30 ноября по 29 декабря включительно. Модель выбирается по Average Precision на валидационной выборке и оценивается на отдельной тестовой выборке. Порядок этапов показан в [архитектурной схеме](architecture.md).

## Входные данные

Для полного запуска поместите архив с синтетическими данными в `data/out.zip`. Исходный архив и генератор хранятся отдельно от GitHub-репозитория.

Контрольный набор создан генератором синтетических телеком-данных TDG версии **1.0.0**, вариант **S**, seed **20260827**. Для повторной генерации выполните команды из каталога с пакетом `tdg`.

```powershell
python -m pip install numpy pandas
python -m tdg --level S --out ./out --seed 20260827
```

Упакуйте созданную папку `out` в `data/out.zip`, сохранив `out/` на верхнем уровне архива. Конвейер читает внутри неё суточные события `out/raw/cdr/`, паспорт набора `out/reference/passport.json` и разметку оттока `out/reference/churn_truth.csv`.

## Запуск через Docker

Запустите Docker Desktop. Из корня репозитория выполните:

```powershell
docker compose run --rm --build pipeline
```

Compose соберёт образ и установит зависимости из `requirements.txt`. Для архива в другой папке задайте абсолютный путь в PowerShell и повторите команду:

```powershell
$env:DATASET_PATH = "C:\путь\к\out.zip"
docker compose run --rm --build pipeline
```

Чтобы снова использовать `data/out.zip` в этом окне PowerShell, выполните `$env:DATASET_PATH = $null`.

## Запуск через Python

Нужен Python 3.12. Из корня репозитория создайте виртуальное окружение, установите зависимости и запустите конвейер:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe pipeline.py
```

Альтернативный путь к архиву можно передать аргументом:

```powershell
.\.venv\Scripts\python.exe pipeline.py --archive "C:\путь\к\out.zip"
```

В [config.json](config.json) заданы дата прогноза, окна наблюдения, параметры моделей и путь вывода. По умолчанию обучение работает на CPU, журнал этапов выводится в терминал.

## Артефакты

При запуске через Python результат сохраняется в `artifacts/result.zip`. При запуске через Docker Compose архив появляется на хосте в `artifacts/docker/result.zip`. В обоих случаях архив содержит четыре файла.

| Файл | Содержимое |
| --- | --- |
| `features.parquet` | Ключ абонента, восемь признаков и метка оттока. Одна строка соответствует одному абоненту. |
| `model.joblib` | Выбранная обученная модель. Для логистической регрессии объект включает масштабирование признаков. |
| `metrics.json` | Метрики обеих моделей на валидации и итоговые метрики выбранной модели на тесте. |
| `data_quality.json` | Границы периодов, пропущенные суточные файлы, число прочитанных и принятых записей и итоговый размер выборки. |

В контрольном запуске сформирована выборка из **186 405 абонентов**. Случайный лес показал на тестовой выборке **ROC-AUC 0,6562** и **Average Precision 0,1068**.

## Проверка

Автоматический тест создаёт небольшой синтетический набор и проверяет разбор дат, обработку дубликатов и границу между признаками и прогнозом. Запустите его после установки зависимостей.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```
